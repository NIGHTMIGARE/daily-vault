# 软件测试度量指标的分类

## 1. 原题
**题干：** 以下（）不属于测试度量指标。
**选项：**
- [ ] A. 故障率
- [x] B. 平均故障恢复时间
- [ ] C. 测试准备时间
- [ ] D. 测试完成时间
**我的答案：** 未作答 / 错误（若答错）
**正确选项：** B

## 2. 知识点
- **核心概念：** **软件测试度量**用于量化评估测试活动的有效性、效率以及软件产品的质量。
- **主要分类：**
  1.  **产品质量指标：** 关注软件本身的质量特性。
      - **例如：** 故障率、缺陷密度、平均无故障时间。
  2.  **测试过程效率指标：** 关注测试团队的工作效率和资源利用。
      - **例如：** 测试准备时间、测试完成时间、测试用例执行效率、缺陷发现率。
  3.  **测试充分性指标：** 关注测试的覆盖范围和深度。
      - **例如：** 需求覆盖率、代码覆盖率。
- **关键区分：** 测试度量 vs. 运维度量
  - **测试度量** 聚焦于**开发测试阶段**，目标是**预防和发现**缺陷。
  - **运维度量** 聚焦于**生产运行阶段**，目标是**保障和恢复**服务。

## 3. 详细解析
1.  **逐项判断：**
    - **A. 故障率：** 核心的**产品质量指标**。测试阶段通过估算或实际发现的故障率来评估发布风险。**属于测试度量。**
    - **B. 平均故障恢复时间：** 衡量系统故障后恢复服务的速度。这是**运维团队（如SRE）** 的核心关注点，用于评估系统可用性和维护性。**不属于测试度量。**
    - **C. 测试准备时间：** 典型的**测试过程效率指标**。测试经理用它来评估计划准确性和资源分配。**属于测试度量。**
    - **D. 测试完成时间：** 典型的**测试过程效率指标**。用于跟踪项目进度和成本。**属于测试度量。**

## 4. 错误选项分析
- **如果误选A：** 可能混淆了“故障率”和“平均故障恢复时间”，未能理解故障率是衡量产品质量的关键，而测试的核心目标就是评估和控制产品质量。
- **如果误选C或D：** 可能对测试度量的范围理解过窄，忽略了测试过程本身的效率度量也是测试管理的重要组成部分。

## 5. 记忆技巧与总结
- **一句话总结：** 测试关心“**找bug和防bug**”的效率与效果；运维关心“**系统挂了怎么办**”。
- **判断口诀：** “**恢复时间运维管，故障多少测试看**”。
- **考试技巧：** 看到“**恢复**”、“**修复**”、“**解决**”等与“事后处理”相关的词，要警惕它可能属于运维范畴而非纯测试范畴。

## 6. 巩固练习
**练习1：**
以下哪个指标最常用于评估测试团队发现缺陷的效率？
**答案：** B. 缺陷移除率
**解析：** 缺陷移除率是评估测试有效性的核心过程指标。平均故障恢复时间（C）是运维指标。

**练习2：**
（多选题）下列指标中，属于软件测试过程度量指标的有（）。
**答案：** A, B, D
**解析：**
- A（执行效率）和D（需求覆盖率）是典型的过程效率与充分性指标。
- B（缺陷重开率）反映了测试和开发流程的质量，属于过程度量。
- C（平均无故障时间）是产品上线后的可靠性指标。
