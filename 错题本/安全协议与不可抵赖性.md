# 安全协议与不可抵赖性

## 1. 原题
**题干：** 下列安全协议中，（ ）能保证交易双方无法抵赖。
**选项：**
- [x] A. SET
- [ ] B. HTTPS
- [ ] C. PGP
- [ ] D. MOSS
**我的答案：** 未作答 / 错误（若答错，例如选了B或C）
**正确选项：** A

## 2. 知识点
- **核心概念：** 不同的安全协议因其设计目标和应用场景不同，所提供的安全服务侧重点也不同。
- **不可抵赖性：** 通过**数字签名**和**可信第三方认证**，为通信行为提供事后无法否认的证据，是电子商务协议的关键需求。
- **关键协议对比：**

| 协议 | 全称 | 主要应用场景 | 核心安全服务 | 是否强调交易不可抵赖 |
| :--- | :--- | :--- | :--- | :--- |
| **SET** | 安全电子交易 | 在线信用卡支付 | **身份认证、保密性、完整性、不可抵赖性** | **是，核心目标** |
| **HTTPS** | HTTP over SSL/TLS | Web安全访问 | 服务器认证、保密性、完整性 | 否（主要提供安全通道） |
| **PGP** | 优良保密协议 | 电子邮件安全 | 保密性、发件人认证、完整性 | 有限（依赖信任网络） |
| **MOSS** | MIME对象安全服务 | 电子邮件安全 | 类似PGP | 否 |

## 3. 详细解析
- **A. SET：** 专为金融交易设计，通过**双重签名**等技术，将订单信息和支付信息绑定，并由交易各方（持卡人、商户、银行）进行数字签名。这些签名由权威CA颁发的证书生成，构成了强有力的法律证据，有效防止任何一方抵赖。**这是最符合题意的选项。**
- **B. HTTPS：** 主要目标是建立安全的通信管道，保护数据传输不被窃听和篡改，并验证服务器身份。它不为管道内传输的具体业务数据提供具有法律效力的、针对客户端的不可抵赖性证明。
- **C. PGP：** 虽然使用数字签名可以提供发件人认证和一定程度的不可否认，但其信任模型（Web of Trust）不如SET基于PKI的模型严谨，且其主要应用场景是邮件，而非严格的“交易”。在四选一中，它不是最佳答案。
- **D. MOSS：** 一个古老的邮件安全协议，已被PGP和S/MIME取代，不提供强大的交易不可抵赖性。

## 4. 错误选项分析
- **如果误选B：** 混淆了“安全通信”与“交易不可抵赖”。HTTPS保证了通信过程的安全，但不为业务逻辑本身提供不可抵赖证据。
- **如果误选C：** 知道数字签名与不可否认性相关，但未能区分不同协议的侧重点和应用场景的严格程度。

## 5. 记忆技巧与总结
- **场景记忆法：**
  - 要**网上买东西怕对方不认账**？ -> 想**SET**。
  - 要**安全地上个网**？ -> 想**HTTPS**。
  - 要**发封安全的邮件**？ -> 想**PGP/SMIME**。
- **SET核心：** “**双签名，三方证，交易抵赖不可能**”。

## 6. 巩固练习
**练习1：**
以下协议中，（）在应用层为HTTP通信提供了安全保护，能够确保服务器身份的真实性，但通常不要求客户端持有数字证书。
**答案：** C. HTTPS
**解析：** HTTPS的核心是Web服务器认证和通道安全，普通浏览不需要客户端证书。

**练习2：**
（单选题）SET协议涉及的多方中，不包括（）。
**答案：** C. 政府监管机构
**解析：** SET是商业支付协议，政府监管机构不是其业务流程中的必要参与方。
