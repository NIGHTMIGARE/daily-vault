# 软件确认测试（有效性测试）的目标

## 原题
软件确认测试也称为有效性测试，主要验证（ ）。确认测试计划通常是在需求分析阶段完成的。根据用户的参与程度不同，软件确认测试通常包括（）。

**选项：**
A. 系统中各个单元模块之间的协作性
B. 软件与硬件在实际运行环境中能否有效集成
C. 软件功能、性能及其它特性是否与用户需求一致
D. 程序模块能否正确实现详细设计说明中的功能、性能和设计约束等要求

## 正确答案
**C. 软件功能、性能及其它特性是否与用户需求一致**

## 解题分析
- **确认测试**，又称**有效性测试**，其核心目标是**从用户的角度**验证软件是否满足了用户在合同中定义的、或双方认可的需求。它回答的问题是：“我们造出来的软件是用户真正想要的吗？”
- **选项C** 准确地描述了这一目标，涵盖了功能、性能和其他特性与用户需求的一致性。
- **错误选项辨析**：
  - **A**：描述的是**集成测试**的目标。
  - **B**：描述的是**系统测试**中环境集成测试或**验收测试**的一部分，不够全面。
  - **D**：描述的是**单元测试**的目标。

## 核心概念总结
### 软件测试级别与目标
| 测试级别 | 英文 | 验证依据 | 核心目标 |
| :--- | :--- | :--- | :--- |
| **单元测试** | Unit Testing | 详细设计说明书 | 验证程序模块的正确性 |
| **集成测试** | Integration Testing | 概要设计说明书 | 验证模块之间的接口与协作 |
| **系统测试** | System Testing | 需求规格说明书 | 验证整个系统作为产品是否符合规格 |
| **确认测试** | Validation Testing | **用户需求/合同** | **验证软件是否满足用户要求，解决实际问题** |

### 确认测试的特点
1.  **用户视角**：测试的出发点和最终判断标准是用户的需求和期望。
2.  **计划先行**：确认测试计划在**需求分析阶段**就开始制定，与需求紧密关联。
3.  **包含验收测试**：根据用户参与程度，确认测试通常包括**Alpha测试**（开发场地，用户在场）和**Beta测试**（用户场地，用户操作）。

## 易错点
- 混淆**系统测试**和**确认测试**。系统测试是**验证**（Verification：“我们是否正确地构建了产品？”），依据是需求规格说明书；确认测试是**确认**（Validation：“我们是否构建了正确的产品？”），依据是用户需求。
- 混淆**集成测试**和**确认测试**。集成测试关心技术上的模块连接，确认测试关心业务上的用户满意。
