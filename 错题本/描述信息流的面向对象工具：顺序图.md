# 

## 原题
在面向对象方法中，信息流是通过向参与者或内部对象发送消息形成的。（ ）用于描述进出系统的信息流。

**选项：**
A. 状态图
B. 顺序图
C. 数据流图
D. 流程图

## 正确答案
**B. 顺序图**

## 解题分析
- **题干语境**：明确限定在 **“面向对象方法中”**。
- **面向对象的信息流**：体现为**对象之间消息的传递**。
- **顺序图** 是UML中专门用于描述**对象之间消息交互顺序**的图，它清晰地展示了在特定场景下，消息是如何在参与者与系统对象之间、以及系统内部对象之间传递的，完美符合“描述进出系统的信息流”。
- **为什么不选C（数据流图）？**
  - **范式错误**：数据流图是**结构化分析/设计方法**的核心工具，其哲学基础是**功能分解**和**数据流动**。
  - **元素不匹配**：DFD由处理、数据流、数据存储、外部实体构成；而面向对象模型由对象、类、属性、操作、消息构成。
  - **在面向对象体系中，DFD不是标准建模工具**。

## 核心概念总结
### 顺序图
- **用途**：按时间顺序描述对象之间的交互。
- **核心元素**：参与者、对象生命线、消息、激活条。
- **优势**：直观展示消息的先后次序和调用关系。

### 顺序图 vs. 数据流图 (关键区别)
| 方面 | 顺序图 | 数据流图 |
| :--- | :--- | :--- |
| **范式** | 面向对象 | 结构化 |
| **核心** | 对象、消息 | 处理、数据流 |
| **动态性** | 强，显示时间顺序 | 弱，不关心时间，只关心逻辑流向 |
| **在OO中的地位** | 标准交互图 | 非标准，通常不使用 |

## 易错点
- **忽略题干语境**：这是最常见的错误。题干明确“在面向对象方法中”，这就排除了属于结构化范式的数据流图。
- **混淆“信息流”的表示方式**：在OO中，信息流是“消息”；在结构化中，信息流是“数据流”。虽然中文都叫“信息流”，但其背后的模型和表示法完全不同。
